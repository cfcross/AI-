# 档口物料 · 统一演示入口（demo）

## 用途
给商贩试用：不需要懂 JSON，也不需要先准备好素材。说一句话，自动路由到
**价目表引擎**（assets/price_board.py，四套模板）或 **海报引擎**（assets/poster_a.py，模板 A），
缺的文案从白名单池补齐，店名按规则代拟，底图没有实拍就 AI 生成。

商品、规格、价格、单位和真实店名按商户原话保留。允许按下文规则补充通用文案和代拟店名。

## 电话自动化任务的授权与交付

当调用方提供任务文件和 `generation_policy` 时，先读取并执行该策略：
- 若任务提供 `render_script`，采用现场快速流程：1张 high 底图→固定脚本渲染1版→核图1次→立即交付。直接使用调用方的 design.json 接口，不读引擎源码、不运行 --print-prompt、不重复研究模板。只有执行报错才排查源码。
- 保持画质，不默认生成候选合集。只有商品错误、明显畸形、构图遮字、文字错误等硬缺陷才重做；不为轻微风格偏好反复生成/比较。合格立即交付，不写长篇比较说明。不限积分是授权，不是要求多生图。
- `credit_authorized=true` 表示项目负责人已授权本轮生图消耗积分；`credit_limit=null`、`image_count_limit=null` 表示不设积分和张数上限。无需再次询问积分、数量、是否继续。没有此授权时不得假定任何使用者都已授权付费。
- 将同一授权传递给后续 miora 或其他内置生图技能。生成前复述只作进度通知，不是审批步骤；不要用 AskQuestion 等待确认。
- 优先选当前实际可用的内置生图模型中最适合任务、画质最高的模型及高质量档位；不为省积分选低质量。不虚构模型名/参数；工具没暴露选择则如实记录。
- 核对食材、文字、价格；有明确硬缺陷可修正或重做。快速模式只渲染最终选定底图，不逐版排版。候选和底图不列入最终打印清单。
- 电话自动化模式不等待人工选图。价格或单位缺失不能编造，按调用方协议写 `needs_input` 后结束；服务或工具持续失败写 `failed`，不要以纯色底冒充生图成功。
- 使用调用方规定的进度、结果文件，最终只交付选定的成品。不得绕过平台强制权限审批、购买或充值。手动普通对话仍遵守其实际授权。

## 接住一句话（核心流程）

先处理商品/场所/菜品/店名的角色，遵循 [菜市场语言与纠偏规则](references/market-language.md)。商品和同义场所词典在 [market-lexicon.json](references/market-lexicon.json)，按相关类别查阅。电话任务先读 language_analysis：已校正 transcript 是网页显示的最终文字；保护明确店名，不把商品主题当店名，不擅自应用 uncertain 候选。海鲜市场、鱼类市集、鱼摊共享水产意图，但保留场所规模；鱼汤也是合法菜品。数字/单位不因纠偏变化。

市场明细的品名、规格和待核实原词见 [market-catalog.json](references/market-catalog.json)。优先使用任务的 catalog_context/source_review 和别名线索，不全表扫描；参考候选不是订单，不自动补商品、规格或价格。大闸蟹公母与重量、白鳝脆/不脆、马鲛丸配料等按口述保留，来源疑点不作为自动纠错目标。真实店名继续等待调研补充。

商贩的输入很模糊，按五步走：

1. **判断产出物**

| 输入里有什么 | 产出 |
|------|------|
| 品项价格（"鲈鱼28一斤…"） | 价目表 |
| 说卖什么、想挂点什么（"我卖鱼的""给我弄张挂的"） | 海报 |
| 两者都有 | **两张都出** |
| 只说"价格牌/价目表/换个价" | 价目表 |
| 只说"海报/招牌/挂的" | 海报（**不追问照片**，没图就 AI 生成） |
| 分不清 | 出海报（门槛最低，商贩一看就懂），并告知还能出价目表 |

2. **抽取**：店名（有就记，没有就代拟）、品类、品项。品类按关键词推断（鱼/虾/蟹→水产；烧鹅/叉烧/卤→烧腊；排骨/牛羊肉→肉档；菜→蔬菜；果→水果；小吃/粉面→小吃），推断后作进度通知并继续。

3. **补缺**（能补就别问）：
   - **文案**：从 `references/copy-pool.md` 按品类挑选，**不现场编写**。
   - **店名**：按下面「店名代拟」规则补一个，在进度通知行里说出来即可。
   - **底图**：有实拍用实拍，没有就 AI 生成，详见「海报配图」。
   - 营业时间、编号、产地、区域，商户没给就留空，不猜。

4. **必要信息**（电话自动化按协议写 needs_input，不停在聊天确认）：
   - 出价目表且没给价格 → "品名和价格按这个格式发我：`鲈鱼 28/斤；大虾 68/斤`"——**价格绝不能编**。
   - 出海报 → **不问价格**（海报本身不写价）。
   - 核心商品或真实店名存在无法消解的歧义时遵循上面的语言规则，不能靠猜测生成错误内容。其余非必要信息按代拟规则处理。

5. **生成前一行进度通知**：说明店名、物料类型、底图方式、预计候选数量及文案，然后直接执行。电话自动化任务的积分授权已在任务策略中给出，不再等待费用或张数确认；候选数量可按质量调整。

## 店名代拟（不用追问）

海报和价目表都不是营业执照，招牌气质对就行。商贩给了什么，就顺着补：

| 商户说了什么 | 店名写法 | 例 |
|------|------|------|
| 只报姓 | 老/小 + 姓 + 品类 | 老李鱼档、小陈肉档 |
| 报姓、铺子感 | 姓 + 记 + 品类 | 陈记烧腊、李记鲜肉 |
| 报花名/称呼 | 花名 + 品类 | 阿珍菜档、强仔水果 |
| 说了位置 | 位置 + 品类 | 巷口鲜肉、市场尾鱼档 |
| 什么都不说 | 品类 + 档 | 鲜鱼档、烧腊档 |

- 不写"正宗""第一""老字号""有限公司"这类词；不暗示年份、传承。
- 代拟的名字**必须出现在进度通知行里**（"先按'老李鱼档'写着"），商户改一个词就行，不要为此单独追问。
- 商户后来报了真名，直接替换重出，不啰嗦。

## 海报配图（三条路，能出图就行）

| 手上有什么 | 怎么走 |
|------|------|
| 商户发了照片 | 直接用，引擎自动裁切铺满（构图不合适调 `pos`，如 `"50% 30%"`） |
| 没照片 | **AI 生成符合品类的近景底图并择优**，授权模式可按效果生成多个候选 |
| 生图不可用 | 电话自动化任务按协议写 failed；普通手动对话可明确说明后用 `--tone` 色调底草稿 |

照片糊、主体太小、带水印——**不让商户重拍**，直接换成 AI 生图这条。商贩的耐心只有一轮。

### AI 生图怎么走

1. **取提示词**（引擎内置，已调好）：
   ```bash
   python assets/poster_a.py --print-prompt --cat "海鲜 · 水产区"
   python assets/poster_a.py --print-prompt --cat 烧腊 --subject "挂满烧鹅的档口近景"
   ```
2. **生成**：走 WorkBuddy 内置图片生成（如当前可用的 `miora-creative-core` → `miora-image-generation`），将任务的积分授权和质量策略一并传递。纯文字需求用文生图；优先实际可选的最佳质量模型和档位，**竖版 2:3，至少 1024×1536，工具支持时优先更高清输出**。若没有 miora，使用其他实际可用的内置图像工具。保留品类提示词及无文字要求，可按核图结果调整构图和细节。
3. **拿到本地文件路径**，喂给海报引擎：`--bg <路径>`。
4. **底图里绝不能有字**。标题、店名、卖点全部由引擎叠字——AI 渲染中文必糊。提示词末尾已经写死这条，不要删。

### 多版 / 选风格

商户说"看看别的样子"，可换 `--subject` 或 `--tone` 生成候选。电话自动化模式自主比较并交付最优成品，不停下来等人选择；普通手动对话可让商户选。**画幅必须统一 2:3**。

## 品类 → 默认模板

| 品类 | 价目表 tpl | 海报 tone |
|------|---------|---------|
| 水产、海鲜 | `t1` 黑板手写 | `seafood` 深青 |
| 肉档 | `t1` | `meat` 暗红 |
| 烧腊、卤味、熟食 | `t2` 老票据 | `roast` 暖琥珀 |
| 蔬菜、菌菇 | `t1` | `veg` 深绿 |
| 水果 | `t3` 红黄排档 | `fruit` 暖橙 |
| 小吃、快餐 | `t3` | `snack` 砖红 |
| 示范点/品牌升级场景 | `t4` 极简墨绿 | — |

拿不准可 `--all-tpl` 比较模板；电话自动化模式自主择优，只交付最终成品。海报的 `tone` 不传会按 `cat` 自动推断。

## 引擎调用（本包自包含，全部相对路径）

先定位本 skill 目录（SKILL.md 所在目录），以下命令在该目录下执行：

```bash
# 价目表：一条数据出四版（挑风格）
python assets/price_board.py --batch stalls.json --all-tpl --out ./out
# 定了风格，批量
python assets/price_board.py --batch stalls.json --tpl t1 --out ./out
# 品项多换 A3
python assets/price_board.py --batch stalls.json --tpl t2 --paper a3 --out ./out

# 海报：批量（示例数据可直接跑，底图缺省走色调底）
python assets/poster_a.py --batch assets/sample-posters.json --out ./out
# 海报：AI 底图
python assets/poster_a.py --name 老李鱼档 --cat 海鲜 --line "凌晨到货 · 卖完收档" \
    --side1 凌晨到货 --side2 卖完收档 --bg ./gen/li_fish.png --out ./out
# 海报：只要提示词
python assets/poster_a.py --print-prompt --cat 水产
```

- 价目表数据核心字段：`key/name/locale/sub/foot/groups`（groups 里是 品名 n / 价格 p / 单位 u / 特价 hot）。
  示例：`assets/sample-stalls.json`，可直接跑通。
- 海报数据核心字段：`key/name/en/cat/line/side1/side2` + 底图三选一 `photo`（实拍）/ `bg`（AI 图）/ 不填（色调底），可选 `pos/tone/top_en/top_cn/no`。
  示例：`assets/sample-posters.json`。
- 底图路径写错不会崩，引擎会退回色调底并打一行 warn。
- 输出 `out/<key>.png`（2x）+ 同名 html，改字可直接改 html 重截。
- 依赖：Python 3 + 本机装有 Chrome 或 Edge（渲染用无头浏览器截图）。
- Windows 下引擎内部截图必须用反斜杠绝对路径——引擎已处理，调用方传普通路径即可。
- 品项 >13 个提醒换 A3；>15 个必须 A3 或拆两张。

## 硬约束

- **价格不编**：价目表的品名与价格必须商户亲口给。区号、营业时间、产地、编号、特价标记同理，没给就留空。
- 海报不写价格，也不问价格。
- 店名可代拟（按上表），但要在进度通知行里说明；不写夸大、涉资质、暗示年份的词。
- 海报底图不出现任何文字（AI 生图必须写死这条），文字只由引擎叠加。
- 不出现 AI 字样、不出现电话交互说明。
- 版式参数不动；要另一种气质换 `--tpl`（价目表）/ `--tone`、`--subject`（海报底图）。
- 海报默认 `--mode print`（打印安全：整体提亮、压暗减弱，防止打印出来发黑）；只在明确只用于屏幕展示时才用 `--mode screen`。批量 json 可逐条写 `"mode"`。

## 文件
- `assets/price_board.py` — 价目表四模板引擎 + 自动字号适配 + 渲染
- `assets/poster_a.py` — 海报模板 A 引擎 + 底图提示词生成 + 渲染（实拍/AI/色调底三种入口）
- `assets/sample-stalls.json` — 可直接跑的价目表示例数据
- `assets/sample-posters.json` — 可直接跑的海报示例数据（未带底图，走色调底）
- `references/copy-pool.md` — 按品类的文案白名单池（价目表 sub/foot/note + 海报 line/side1/side2）
