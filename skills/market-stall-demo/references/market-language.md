# 菜市场语言理解与纠偏

词表在同目录 `market-lexicon.json`：categories 是用户平面图的22类和常见商品扩充；venue_groups 是场所语义组；alias_groups 是地方叫法；confusions 是需上下文验证的误识别候选；never_merge 是不可擅自合并的商品。词表不是实时库存、价格、产地或真实店名名单。registered_store_names 目前为空，待现场调研。

## 先明确角色，再进行设计

1. 已登记或明确“店名叫/招牌写”的名称优先保护。名字特殊不是纠错理由。没有店名时记录未提供，再按代拟规则产生泛称，并在 summary 标注。不要把“做一张东星斑的海报”解释成店名叫东星斑。
2. “海鲜市场/鱼类集市/鱼类市集/鱼摊/水产档”同属水产销售意图，能推断画面主题；保留用户描述的市场、集市、单摊规模和原叫法。市场海报不自动变成单家鱼档广告，不能从场所名推导任意商品价格。
3. 商品与菜品要区分：“鱼汤十五元一碗”是菜品；“给我的鱼汤做个招牌”可能是鱼摊误识别，但若用户明确把鱼汤作为店名、菜名或品牌，应保留。孤立“鱼汤海报”保留鱼汤，不自动纠成鱼摊。
4. 罗非鱼/鲈鱼、龙利鱼/巴沙鱼、普通草鱼/脆肉鲩、鳕鱼/银鳕鱼不能仅凭语义接近互换。保留品种、部位、规格、产地限定及每个数字/单位。

## 电话自动化任务

程序的 language_analysis 已在网页展示前完成保守词表纠偏，text 是最终文字；raw_text、edits 是审计记录；terms/venues 是基于词表的角色线索，不能把它们当作完整商品订单（否定、举例、比较中的词也可能命中）。protected_names 必须保留，uncertain 只是候选，不是批准替换。

- 采用已校正的 transcript 和 edits，原文仅用于理解和追溯，不能把已纠正的错字再恢复。
- 对 uncertain 和词表外词结合完整语境理解，但不要在生图阶段偷偷改商品、金额、单位或店名，造成网页和图片不一致。原文存在完整合理解释时保留；核心商品确实无法判定时按调用方协议 needs_input。手动聊天可简短询问。
- 优先使用任务内 terms/venues；仅需额外领域知识时读取词表相应类别，不每轮研究整本词表，不新增生图候选轮次。
- 提交 design 前检查：店名来自明确命名或标明代拟；画面商品来自最终需求；价格数字和单位与原文对应。用正常语言理解否定和范围，例如“不要罗非鱼，要鲈鱼”只画鲈鱼，“鱼汤不要改成鱼摊”保留鱼汤。

## 判例

| 输入 | 处理 |
| --- | --- |
| 东兴班每斤八十八元 | 商品候选东星斑，88元/斤；未提供店名 |
| 帮我做一张东兴班的海报 | 商品主题东星斑；不能用东兴班作店名 |
| 店名叫东兴班，卖鲈鱼 | 店名东兴班，商品鲈鱼 |
| 东兴班海鲜档，帮我做海报 | 可能的真实档口名，保留名称 |
| 给我的鱼汤做个招牌 | 程序存在明确场所依据时校正鱼摊；明确命名优先 |
| 鱼汤十五元一碗 / 做一张鱼汤海报 | 保留鱼汤 |
| 鱼类市集海报 / 海鲜市场海报 | 水产集市/市场场景，不擅自缩成单摊 |
| 濑尿虾、通菜、牛展 | 理解地方叫法，保留用户的用词 |

## 维护

真实错例先进入 confusions，再在项目 tests/test_market_language.py 添加正例、反例和特殊店名例。不能把同音词全部加入无条件替换表。不要从一次对话自动学习价格、真实店名或新替换规则。普通话/粤语均使用规范汉字词表；当前本地纠偏是显式候选和上下文规则，不是通用拼音/粤拼模糊匹配模型。
